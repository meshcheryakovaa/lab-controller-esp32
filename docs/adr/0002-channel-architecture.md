# ADR-0002. Канал как центральная сущность; handles вместо строк; data plane отдельно от event bus

**Статус:** принято (Milestone 0)

## Context

Дашборды, графики, PID, правила, эксперименты и логгер должны получать данные так,
чтобы ни один из них не знал о существовании конкретного датчика. При этом система
работает на 240 МГц с ~300 КБ доступной кучи и должна выдерживать десятки каналов
с частотами до 80–1000 Гц.

## Decision

1. **Channel** — единственная точка доступа к данным. Всё выше уровня драйвера
   адресует данные через `ChannelHandle`.
2. **Handles, а не строки.** `ChannelHandle` — `uint16`, равный `index + 1` в массиве
   фиксированной ёмкости. Пользовательский ключ (`"mass_01"`) живёт в дескрипторе и
   на границе REST/конфигурации. Удаление канала оставляет дырку — handles остальных
   каналов не меняются.
3. **Три значения на отсчёт:** `raw`, `calibrated`, `processed`.
4. **Data plane отдельно от EventBus.** Отсчёты доставляются собственным
   типизированным списком слушателей `ChannelManager`. `EventBus` несёт только
   control-plane события. `CHANNEL_UPDATED` существует, но включается поканально.

## Alternatives

* **Строковые id везде.** Читаемо в отладке, но 20 каналов × 80 Гц × `strcmp` — это
  заметная доля кадра, а `String` в цикле — фрагментация кучи.
* **Все отсчёты через EventBus.** Единообразно и красиво, но 1600 диспетчеризаций в
  секунду через универсальную шину с проверкой масок — чистые накладные расходы,
  плюс любой подписчик «на всё» начинает получать поток данных, который ему не нужен.
* **Хранить только processed.** Экономит 8 байт на канал. Делает невозможным
  пересчёт эксперимента после уточнения калибровки, то есть ломает §48.

## Consequences

**Плюсы.** Горячий путь — индексация массива. Переименование канала пользователем не
рвёт открытые графики. Сырые данные сохранены для воспроизводимости. Подписчики
получают ровно то, на что подписались.

**Минусы.** Двойная адресация (ключ ↔ handle) требует аккуратности на границе API.
Дырки в массиве после удаления делают итерацию O(capacity), а не O(active) — при
96 каналах это несущественно. 12 байт на канал вместо 4.

**Следствие для WebSocket.** В кадрах телеметрии используются handles, а актуальность
дескрипторов отслеживается через `config_revision`.
