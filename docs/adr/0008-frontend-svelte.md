# ADR-0008. Svelte 5 + TypeScript + Vite, один бандл, gzip в LittleFS

**Статус:** принято (Milestone 0)

## Context

SPA должен помещаться в раздел LittleFS 640 КБ вместе с конфигурацией пользователя,
отдаваться контроллером на 240 МГц, оставаться отзывчивым при обновлении десятков
значений 5–10 раз в секунду и работать на планшете и телефоне у установки.
При этом он должен строить формы конфигурации автоматически из манифестов.

## Decision

Svelte 5 + TypeScript, сборка Vite в один JS- и один CSS-файл без code-splitting.
Pre-build хук PlatformIO собирает frontend, gzip-ит артефакты и кладёт в
`firmware/data/www`; прошивка отдаёт `.gz` напрямую с заголовком
`Content-Encoding: gzip`.

Графики — uPlot. Бюджет: **≤ 250 КБ gzip на всё**.

## Alternatives

* **Preact + TypeScript.** Рантайм ~10 КБ, React-совместимый API, богатая экосистема
  (готовые grid-layout компоненты для дашборда). Проигрывает в том, что сохраняет
  diff-проход virtual DOM на каждое обновление; при частых точечных обновлениях
  числовых полей это лишняя работа на слабом клиенте.
* **Vue 3.** Удобные формы и реактивность, но рантайм ~35 КБ gzip и больше накладных
  расходов.
* **Vanilla TS + Lit.** Минимум зависимостей и максимально предсказуемый размер,
  но заметно больше ручной работы на drag-and-drop дашборде и редакторе экспериментов.
* **Chart.js / ECharts вместо uPlot.** В 3–10 раз тяжелее и ощутимо медленнее на
  тысячах точек на мобильном устройстве.

## Consequences

**Плюсы.** Маленький бандл; отсутствие рантайма фреймворка; компиляция в прямые
операции с DOM — плавно даже на планшете. TypeScript даёт типизированное зеркало
модели прошивки (`lib/types.ts`), поэтому расхождение с API ловится при сборке.
Один файл вместо десятков чанков — меньше HTTP-запросов к слабому серверу.

**Минусы.** Экосистема готовых компонентов беднее, чем у React; drag-and-drop сетку
дашборда, вероятно, придётся писать самим (~200 строк). Svelte 5 (runes) относительно
свеж — часть примеров в сети написана для Svelte 4.

**Контроль.** `chunkSizeWarningLimit: 200` в Vite и проверка размера артефакта в CI;
превышение бюджета — повод для ревью, а не для увеличения раздела.
